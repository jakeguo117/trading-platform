REVIEW + METHOD LAB
A

确定性 TradeEpisode

程序计算净盈亏、费用、滑点、持有期、MAE/MFE、执行偏差与规则遵守度。

B

LLM 盲结果过程审计

先隐藏最终盈亏与未来价格，只判断当时信息下的决策和执行是否合规。

C

LLM 结果复盘

再开放结果；输出 FACT / INFERENCE / HYPOTHESIS / UNKNOWN，不把推测写成原因。

D

一个有界候选 diff

一次只改变一个规则或参数族；策略、风险、数据合同、成本模型不能夹带修改。

E

预注册与独立验证

PIT、walk-forward、OOS、费用/流动性、负对照、一次性 sealed blind 与多重检验控制。

F

资格、批准、激活分离

程序给 EligibilityReport；Jake 对精确 hash 批准；另一步原子激活并保留显式回滚。

正常终点： NO_HYPOTHESIS / INELIGIBLE / REJECTED → 不改规则，保留证据。
合格路径： ELIGIBLE → APPROVED_NOT_ACTIVE → ACTIVE → SUSPENDED / ROLLED_BACK。
虚线异步反馈：新规则只影响未来获准运行；绝不回写当前决策，也不自动迁移在途仓位。

开工前必须定义的脆弱点

这些 P0 会改变状态模型、权限边界或核心数据合同，不能留到实现中临时决定。

P0 ARCHITECTURE BLOCKERS
P0 · DATA SEAM

Broker Bridge 尚未闭合

宿主可见工具不等于本地 Plugin 可程序调用。必须证明 typed、只读、无 LLM ETL 的 seam。

P0 · AUTHORITY

权威 Broker / Account

IBKR 与 Robinhood 不能混合或 fallback；账户、sizing scope 和数据资格必须唯一绑定。

P0 · IDENTITY

卡片如何绑定人工订单

需要 decision_id、intent_id、group_id、order_id、execution_id 与 cancel-replace lineage，不能按合约猜。

P0 · STATE

部分成交与人工偏离

组合意图不保证整组成交；需处理 legging、cancel pending、改单、拒绝、bust/correction。

P0 · TIME

“实时”没有合同

需冻结 source/event/receive/seal/decision 时间、DST、session、最大年龄与跨域跨度。

P0 · OPTIONS

“完全平仓”没有终局定义

残余腿/股份、assignment、exercise、adjustment、费用晚到和成交修正都会推迟 CLOSED。

P0 · POLICY

可操作交易规则仍未冻结

生产 Breakout、carrier、退出与 Risk Policy 仍不完整；Long Call 与 BCS 会产生不同状态模型。

P0 · RECOVERY

幂等、并发与崩溃恢复

必须定义重复运行、锁、断点恢复、原子写、执行去重、损坏状态与重建 latest。

P0 · VERSIONING

新规则如何影响旧仓

默认建议 position group 固定开仓时 lifecycle 版本；任何迁移必须另行批准。

P0 · RESEARCH

单笔复盘与过拟合

触发假设的交易不能再当 OOS；blind 只打开一次；还需保存 NO_ACTION 与未成交机会。

P0 · PRIVACY

原始账户数据与凭证

凭证只留 Connector；原始 payload、LLM 输入、日志、保留期限与 provider 许可需定义。

P0 · CARD

卡片失效与 supersede

时间、报价、持仓、订单、session 或规则变化都应使旧卡失效；同一窗口只能一张 active card。

P1 · 原型后、真实 ACTION_PLAN 前

对账刷新节奏、slippage/MAE/MFE 指标、LLM review schema、候选样本与门槛、property/crash/replay tests、备份与状态修复。

P2 · 明确延后

SLV 生产、多账户/第二 Broker、后台 streaming、主动通知、组合优化、自动发布、任何 broker 写入或自动交易。
